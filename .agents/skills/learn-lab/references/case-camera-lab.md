# 案例：一节相机课的三次重做

**适用**：第二档 3D 课，或主体为实体物件（机械、光学、生物结构）的课；想知道一节好课要考虑什么、效果怎么配。
**不适用**：第一档课；抽象概念课（矩阵、注意力、算法步骤）只借「可以推广的部分」一节，其余规则针对实体物件，硬套会带偏。

来源：2026-09-29 摄影课实测，同一个主题前后做了三版，另以 Ryan Sael 的镜头实验室作参照。其他领域的课做出来之前，下面除「可以推广的部分」外都只在这一类课上验证过。

## 三版各改了什么

| 版本 | 做法 | 学习者的反馈 | 学到的 |
| --- | --- | --- | --- |
| v1 | 单文件，美术要求只写「精美」「产品渲染质感」 | 不如参考作品精美 | 形容词换不来质感，实测得到的是暗色圆台上一个孤零零的物体 |
| v2 | 按五项美术规格重做，加爆炸图、光路图 | 好多了，但「我们现在就是一个 3D」 | 美术规格只管质感。课展示物体，非现象 |
| v3 | 主题改「按下快门，一张照片是怎么被做出来的」：相机对 1:10 微缩布景，副相机按物理实时算取景画面，调任何参数照片跟着变 | 不再「只是一个 3D」 | 主题要落在现象上；画面上的物理效果要和数字出自同一个模型 |

参照：Ryan lens lab 由 Opus 5.5 一次成型，1 小时 26 分钟、$25.66（2026-09-23 推文自述）。转对焦环，镜片移动，清晰面在场景前后移。同样以现象（清晰面移动）为中心。

## 一节好课要考虑的

1. **先定现象，再搭场景**。v3 的现象是清晰、亮度、拖影三件事，布景按现象来摆：人偶在对焦距离 1.5m 上，作为对焦主体；风车在 3.5m，一直转，快门慢时拖影；灯串在 7m，焦外时变成光斑，也用来看曝光。每件道具都对应一个现象，没有纯装饰的道具。
2. **所有输出出自同一份 state**。叶片、快门帘、光锥、景深板、取景画面、测光表、图表点、叙述，全由同一 state 算出。画面效果与数字卡共用纯函数（`optics.js`），核验脚本也调它（33 项独立对照通过）。
3. **预设标题要算出来**。「全清」预设的标题凭直觉写成「f/16 前后都清楚」，但景深函数算出的清晰范围只有 1.17–2.08m，因此将标题改为「收光圈」，并如实标注范围。
4. **拍摄时冻结全部状态**。照片冲洗时用了冲洗那一刻的 ISO，和照片说明对不上。「快照」类动作须存下增益、噪点等全部参数。
5. **多机位讲同一现象**。总览、拍摄、剖视三机位，各看现象一面。每机位自动构图，主体占画面 55–65%，不被面板挡。
6. **先预测不能丢**。v3 的需求另行手写，没有从 spec 派生，导致「先预测」这一步在转写时丢失。本课至今未补。

## 效果怎么配

效果分两类，配法不同：

| 类别 | v3 里的例子 | 规则 |
| --- | --- | --- |
| 承载现象 | 薄透镜景深：光圈圆盘上偏移采样，平移视锥保持对焦面；运动模糊：快门时间内随机取时刻；曝光增益 2^(EV场景 − EV设置)，经 ACES 和 sRGB 输出 | 须与数字卡出自同一个模型，核验脚本要能独立复算 |
| 只管手感 | 零件倒角、PCFSoft 阴影、GTAO（静止才开）、主画面 BokehPass、风车与浮尘常驻微动、旋钮挡位感、按钮回弹 | 可省；不许与承载现象效果矛盾，不能冒充物理（主画面 BokehPass 是示意，取景画面才按物理算） |
| 示意 | ISO 噪点 | 页面标明示意 |

标定：增益 1 时人偶区平均 sRGB 亮度约 0.49，据此定标定常数，页面内算平均亮度打日志复查。

预算（v3 实测）：自写代码 kit + lab + index.html 共 151KB（上限 220KB）；主画面 draw call 152–178（上限 200）；取景画面每帧 8 样本，参数变先出 4 样本预览，渐收敛到 64 样本。GTAO 开时 draw call 曾顶到 200，给半透明叠加层设 `userData.noDepth = true`，不进 AO 与景深深度通道后降到 178。

## 美术规格

只写「精美」这类形容词，实测得到的是暗色圆台上一个孤零零的物体。须逐条写成规格：

1. **场景**：有地面、墙面、背景展品、植物。主体不能孤立黑底上。
2. **操作件长在台面上**：旋钮、滑轨、仪表做成 3D 模型，可拖动，转动有挡位段落感。
3. **主体细节**：有可见子部件，零件倒角；只用一个主色加一个辅色；只有正在起作用的零件发光。
4. **常驻标注**：胶囊标签加引线，一直显示，不是点击后才出现。
5. **手感**：所有状态变化有缓动；切视图时相机运镜到预设机位；悬停有反馈；场景常驻微动（转动、闪烁、浮尘）。

迭代：截图 → 与参考帧并排 → 写最大 3 个差距 → 改，最多 3 轮。v3 三轮差距可直接当检查项：布景空、道具稀；机位切掉半截控件；主体太小认不出；结果（拍出照片）需操作才出现，截图看不到；金属反射白房间，像塑料。

## 共用套件（`[待验证]`，截止 2026-10-29）

房间、实验台、灯光、面板样式、运镜、缓动、标签、后处理拆到 `kit/`，每课特有部分放 `lab/`，`kit/` 不许 import `lab/`。第一版约 44KB，导出 `createStage`、`createViews`、`createLabels`、`createPicker`、`knob`、`gauge`、`seg`、`modal` 等。新课接法：

1. `createStage({ container, bench })` 拿房间、灯、台面、相机、后处理，台面 y = 0。
2. 自己物体加进 `stage.scene`；每帧逻辑写 `stage.onFrame`；副渲染包在 `stage.renderExtra`，draw call 单独计数。
3. 机位用 `stage.views.define` / `go`；带 `data-dock` 的面板会被自动避让。

设想：第二课起精修成本明显降。验证：用 kit 做第 2 个 lab，记成本，对比 `build-lesson.md` 分档表第二档。第 2 个 lab 若需改 kit 本身，记下改动——说明 kit 边界划错。

## 可以推广的部分

- **现象优先**：任何领域都先问「学习者改一个变量，眼前什么在变」。抽象概念的现象是算出的量在屏上变化，如两个 loss 比值、注意力权重热图。此推广系推断，未经抽象概念课验证。
- **承载现象的效果与数字同源**，手感效果可省、不许矛盾。不依赖领域。
- 场景、材质、台面操作件、光学效果，实体物件课专用。

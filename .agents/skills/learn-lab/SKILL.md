# learn-lab

## 前提

学习效果主要来自四件事：先预测、再操作、看反馈、自己解释，再加上事后检索。画面是第二来源，只在它服务于正在讲的现象时才加分：
- 与内容相关的美术能带来小到中等的正效应；
- 与内容无关的装饰会拖累学习；
- 动画仅在内容本身有变化时优于静态图。

依据见 `references/build-lesson.md` 末节。

**一课 = 一个眼前发生的现象**。学习者改一个变量，现象立刻按真实规律变。只展示物体本身（如相机模型），不管做得多精细，看起来都「只是一个 3D 模型」。

## 流程

1. **拆领域**：把领域拆成 8–15 个概念，标出依赖关系。每个概念写成「学完能预测的 1 件事」，写不出就说明还没拆到够小。产出 `curriculum.md`。
2. **探误解**：每个概念出 2–3 道预测题问学习者。答对的跳过，答错的排到前面。
3. **选形式**：按概念结构选，不按好看选。

   | 概念的结构 | 形式 | 实测情况 |
   | --- | --- | --- |
   | 事实、定义 | 文字+静态图 | 未实测 |
   | 参数和结果的关系 | 2D 交互（滑杆+图） | 已实测 |
   | 随时间展开的过程 | 可暂停、可分段动画 | 未实测 |
   | 空间结构、机械、三维场 | 3D | 已实测（实体物件类） |
   | 有现成标准答案的判断（照片猜 EXIF、代码猜输出） | 检索游戏，反复玩，按误差打分 | 未实测 |

   一个领域就是一组 lab，每课单独选形式，不强求全用 3D。

   「未实测」指这条路径还没做出过课，它是一条按证据推出来的规则，不是经验。第一次走这些路径时，把遇到的意外记下来，那才是这一行的真实内容。
4. **写课规格**（写代码前，一屏内）：
   - 标题提的问题；
   - 发生的现象；
   - 学习者改哪个变量；
   - 改完哪几处同时变；
   - 默认参数下能否直接看到标题说的现象；
   - 「先预测」题怎么问。

   写不出现象的概念不做交互课，退回文字或静态图。模板见 `references/build-lesson.md`。

   三条最易写虚的约束，spec 必须落实：
   - 「默认可见」写成实测数值+阈值；
   - 「先预测」真能选、选完锁住、运行后揭晓；
   - 叙述分支条件用计算结果，不用输入阈值。

   写完跑 `node --experimental-strip-types '<SKILL_DIR>/scripts/check-spec.ts' <spec.md>`，不通过先改 spec，不开工写代码。
5. **做课**：先做第一档（快速单文件）。只有反复用或领域核心的课进第二档精修。规格模板、分档、执行保护见 `references/build-lesson.md`；第二档做细（美术、效果、共用套件）见 `references/case-camera-lab.md`。

   第二档 3D 课**必须**先读 `references/visual-style.md`：色与材质、版面、主体构图、操作件、标签、手感、迭代方法、预算都在那。可复用套件在 `assets/kit/`（相机课 v3 那套，随 skill 走，不依赖外部目录），直接 `cp -R` 到课目录用，不重写。
6. **独立核验**：核验者不能是做课 agent，最好换模型家族。做不到则至少换全新会话 agent，只给课目录和核验方法，不给做课过程。先跑 `node --experimental-strip-types '<SKILL_DIR>/scripts/extract-visible-text.ts' <课目录>`，抽出页面所有用户可见文字清单，逐条判断哪些是教学论断，逐条核对。核验报告由主 agent 先判定误报/属实/待验证，再决定改不改。做法和真实回归案例见 `references/verify-lesson.md`。
7. **讲回来**：学习者三句大白话讲本课，agent 对照 `claims.md` 指出漏的和错的。讲不清的地方，就是下一课。
8. **复习**：每课出 3 道延迟自测题，其中至少 1 道要换情境。排进第 1、3、7 天的复习队列，答案单独放一个文件。
9. **消化复习队列**回答「答错 / 答对后，队列怎么继续流动」：

```text
触发：学习者回来或说「复习」 -> 出到期题（不给答案）
学习者作答 -> 记对错进队列
记对错进队列
  +-- 答错 -> 探误解（回到第 2 步，重新探该概念的误解）
  \-- 答对 -> 复习间隔翻倍（7 -> 14 -> 30 天，默认做法，可换）
```

## 总览课规则（实体物件 / 系统类领域）

相机、台式 PC、发动机、人体骨骼等「由多个可辨认部件组成的实体或系统」，**第一课必须是总览课**，细课再从总览课某部件展开。

总览课 spec 不套标准模板，改用：

```markdown
# <这个东西由哪些部分组成，每个部分做什么？>
- 学完能预测：拆掉或替换任一部件后，整体功能如何变化
- 展示方式：拆解视图（爆炸图 / 透视图 / 分层拆开），每个部件可点击，点击显示：部件名称、作用一句话、如果没有它会发生什么
- 先预测题：给一台「低配版」，问「把 X 换成高配版，哪个指标改善最明显？」；选项 3 个；选定锁住后，展示模拟结果对比
- 主体配件列表：<逐一列出，要覆盖「初学者可能以为不重要但实际很关键」的那几个>
- 默认参数：<写一套典型低配，让先预测题有说头>
- 升级 / 降级效果：每个配件至少写「升级有感」「降级有感」两个阈值点（不要只写最高配 vs 最低配）
```

总览课形式固定 3D 或带标注 SVG 爆炸图（不做 2D 滑杆课），因「拆解结构」本身是空间信息。

## 停下或转交的条件

- 核验出的错误如果无法在课内修正，就不交付，并报告错在哪里。
- **领域是实体物件 / 系统，但第 1 步拆出的第一课不是总览课** → 停下，报告当前课题和为什么不是总览，由主 agent 决定。
- **第 3 步选了 3D，但主体不是实体物件**（机械、光学、生物结构、电子器件等可直接摸到的东西）→ 停，向主 agent 报告「为什么选 3D」「主体是什么」，由其决定。3D 参照见 `references/case-camera-lab.md`，其规则只在实体物件课实测过，不能默认推广到抽象概念课。
- **第 3 步选的形式标注「未实测」**（静态图+文字 / 动画 / 检索游戏）→ 停下，报告：选了哪条路径、为什么选、预计遇到哪些问题，由主 agent 决定是否继续。不许以「未实测路径没被禁止」为由自行推进。
- **先预测题在页面可见时已能看到答案**（标题透露结论、读数卡直接显示答案、图上数据点已落在正确范围）→ 先预测实现不合格，必须改：锁定预测前，现象、读数卡、图表数据点都隐藏；标题只提问，不给结论。
- **spec 未通过 `check-spec` 就写代码** → 交付物无效，回第 4 步重写 spec 并通过检查再动手。
- 学习者要阶段规划或进度追踪 → 交 goal-roadmap。运行时无此能力则只交付 curriculum，阶段由学习者自定。
- 需付费素材、外部账号，或要把学习者照片、文件、数据传第三方 → 先问。学习者上传的个人素材只本地处理。
- 学习者说「不用做课，直接讲」 → 直接讲，预测题和复习题留后面。

## 输出

- 每次都产出：`curriculum.md`（概念、依赖、「能预测的 1 件事」、探误解结果）；`review-queue.md`（日期 · 课 · 题 · 上次对错），答案另存一个文件。
- 按课形式追加：
  - **交互课**：`lessons/<日期>-<slug>/`，含 `index.html`、`spec.md`、`claims.md`。`claims.md` 四列：论断 · 出处 · 核验方式 · 结论。
  - **静态课**（文字+静态图）：`lessons/<日期>-<slug>/`，含 `lesson.md` 和 `claims.md`。静态课论断同样要核。
  - **直接讲**：不建课目录。只把 2 道预测题和复习题追加进 `review-queue.md`。
- 聊天只回：课路径（有课才回）、一句话说本课学什么、核验未过或未验证条目、下一步动作。

## Trigger Test Cases

```
✓ "我想系统学一下摄影" → triggers
✓ "帮我做个交互课讲清楚过拟合" → triggers
✓ "这个相机课的光路讲得对吗，帮我核一下" → triggers（只走第 6 步）
✗ "帮我把今年的学习目标排个季度路线" → doesn't trigger (→ goal-roadmap)
✗ "过拟合是什么意思？一句话" → doesn't trigger (直接回答)
◐ "我想三个月学会 ML，每周帮我盯进度" → 两个都触发 (boundary: 阶段和进度归 goal-roadmap；每个阶段里的概念拆解、课和复习归本 skill)
◐ "给我讲讲景深" → 默认直接讲，并附 2 道预测题 (boundary: 学习者答错了，或者主动说要练，才进入第 3 步以后)
```

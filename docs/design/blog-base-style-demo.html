结论

这是一套“证据约束下的设计决定”，不是伪造的科学排名。论文提供约束与风险信号，帮助排除部分不稳妥参数，并证明个体差异显著；具体字体仍需以同内容、同字号、同宽度的页面验收收口。

证据研究能支持的结论本方案如何使用强度
Arditi & Cho, 2005控制其他字形变量后，serif 对正常尺寸连续阅读速度没有显著优势。不把 Noto/Source Serif 宣传成“科学上优于 sans”；选择它们是长文编辑气质与字形质量判断。中高
Minakata & Beier, 2022serif 与 stroke contrast 会交互，单独比较 serif/sans 容易混入其他字形变量。评估具体字体的字宽、笔画对比、counter 与屏幕表现，不按类别贴标签。中
Wallace et al., 2022不同人的最快与最慢字体阅读速度可相差约 35%，且不存在一款字体适合所有人。冻结统一默认值，但保留浏览器 zoom/reflow 与未来 reader preference 的兼容空间。中高
Zhu, Su & Dong, 2021115 人简中手机实验中，字号和行距影响阅读时间、难度与视觉疲劳；固定 pt 不能直接换算成跨设备 CSS px。18px 作为可缩放基线，移动端不低于 17px；行距与字号一起验收。中高
Chan & Lee, 2005繁中显示器实验中，字体、字号、行距和极性影响速度；但比较的是 Ming 与 Li，不能推出宋体普遍胜黑体。支持中文需要独立排版参数；不把旧设备结果外推成 Noto Serif SC 排名。中
Huang, Li & Tung, 2018繁体中文手机阅读中，过大的行距会增加滚动并降低速度；较大行距的主观舒适度可能更高。中文正文取 1.80，而不是继续无上限放大；段落间距负责分块。中低
W3C CLReq现代中文专家规范建议横排通常不超过 48 字/行、line-height 常在 1.5–2.0，正文原则上密排。中文段落约 48 字/行、line-height 1.80、letter-spacing normal；这是规范性 guidance，不是因果实验。专家规范
Dyson, 2004每行字符数是屏幕阅读的重要变量，但研究不足以推出唯一最佳行宽。英文 68ch、中文约 48 字作为当前阅读基线，不声称是唯一科学值。中高综述
Legge & Bigelow, 2011流畅阅读更接近由视觉角度与实际 x-height 决定，而不是固定 CSS px。18px 是产品基线；不阻止缩放，并用实际字体页面而非字号标签判断大小。高综述

中文具体 family 的直接同行评审证据很弱。Bing Zhang 2011 的中文数字字体实验说明：同属黑体的具体设计差异与字距，可能比“宋体/黑体”类别更重要；但它是硕士论文、样本与旧字体有限，只作为候选筛选线索，不作为 Noto Serif SC 胜出的证明。代码字体同样没有可靠论文证明某个 family 或 ligature 最优，因此以字符辨识、防查错和本地使用一致性为验收依据。

学习路线 · 第 3 课

从一个最小循环开始

分类：AI Engineering · 主题：Agent、Harness

一个可运行的 Agent 最少需要三件事：接收目标、选择动作、读取反馈。复杂系统只是在这个闭环上增加状态、边界和验收。

核心判断：先让反馈链可验证，再增加自治程度。没有稳定反馈的自治，只会把错误放大。

基础结构

  • Goal：当前闭环究竟要达成什么状态。
  • Action：模型此刻可选择的有限动作集合。
  • Evidence：系统如何证明动作真的产生了预期结果。
type Loop = {
  goal: Goal;
  act(state: State): Promise<Action>;
  verify(result: Result): Evidence;
};

READING SAMPLE · ENGLISH

Start with the smallest verifiable loop

Category: AI Engineering · Topics: Agent, Harness

An agent needs three things before it needs a framework: a goal it can interpret, a bounded set of actions, and evidence that tells it whether those actions worked. More elaborate systems add memory, recovery, and delegation, but they do not replace this loop.

Design rule: increase autonomy only after the feedback path is observable and recoverable.

Why the distinction matters

A workflow encodes a known route. An agent chooses among routes. A harness constrains and evaluates those choices. Treating these as interchangeable produces systems that look autonomous but cannot explain or repair their own failures.

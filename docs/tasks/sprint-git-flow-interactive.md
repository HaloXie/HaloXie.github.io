# Sprint Git Flow 场景演示

## 范围与验收

核心命题：共享测试组合，同时保留单项改动的交付边界；组合通过不替代最终候选验证。

授权：2026-10-16，按前轮建议实现交互并安排几个读者 agent 挑刺。L 级文件数，先实现独立 lab，再嵌入和验证；不涉及实际生产配置、Git 分支操作或部署。

1. 对照现有文章，固定五种场景的分支内容、测试版本、候选产物与生产产物。
2. 实现确定性 HTML 状态动画，沿用现有主题桥；数据/模型与渲染分开，不新增依赖。
3. 嵌入中文文章，缩短两案例重复解释，保留操作、异常恢复和静态图片。
4. 三名独立 agent 模拟初学者、发布工程师、一般技术读者，修正后复读；执行状态测试、构建、内容门禁和浏览器验证。

关键前提：main 是候选基线；develop 只组织组合测试。原分支完成依赖检查与审查才回主干；tag 固定提交，gray 验证产物，生产部署同一产物。生产恢复不改代码历史。Sprint 重建保存未完成分支和必要修复。

异常覆盖：测试失败回原分支、gray 失败新 tag、生产异常先兼容性检查再恢复、Sprint 重建后重新部署和验证。紧急修复场景明确 main 与生产基线一致。

观测：模型断言 tag 不移动、先验证再部署同产物、A/H 单独发布、B 在重建后保留、生产恢复后主干不变；浏览器检查五场景、前后步、重来、播放暂停、卡片说明、主题与 iframe 高度。

回退：文章保留可展开静态图，lab 自身有 noscript 图。无需改共享代码；撤回交互时恢复文章中的主图入口即可。未新增或替换图片。

## 维护

- 修改 `labs/sprint-git-flow/model.ts` 和 `app.ts`；执行 `node labs/sprint-git-flow/build.ts` 生成浏览器 `.mjs`，不要手改生成文件。
- 执行 `node labs/sprint-git-flow/model.test.ts`。
- CSS 仅作用于独立 iframe 文档，消费 Base token，不修改 Base、主题桥或生产入口。
- 这是分步状态演示，不做完整 Git 模拟器，也不新增学习课程/测验体系。

## agent 模拟试读（不是真人验证）

- 初学者能复述主路径与失败处理；发现术语密集、最终提交验证语义不清。已拆概念段，补 CI/MR/tag/产物释义并说明集成测试与 gray 各验证什么。
- 发布读者发现测试失败被写成必须重建 develop。已修正为重新合入并部署，必要时才协调移除或重建；同步修正文中步骤表。
- 编辑发现手机控件与结果距离远、A/B 角色切换。已补底部前后步及暂停，把卡片说明改为就地展开，案例统一为导出 A/查询 B，去掉图内重复的长结论。

# 博客配图

本博客的项目技能，权威源在 `docs/skills/blog-imagegen/`，仓库 `.agents/skills/blog-imagegen` 链接到本目录。角色与构图属于本站约定，不作为通用插画标准。

## 权威与范围

先读仓库根目录 [AGENTS.md](../../../AGENTS.md) 的配图规范与 [已确认风格 Prompt](../../design/blog-image-style-prompt.md)，再实际打开参考图。两类插图共用本站画风与交付规格，不复制另一套全局风格。使用角色时，必须读取 [角色与教学互动](references/characters.md)，并打开其中对应的视觉参考。

文章专用 Prompt 放在 `docs/design/<post-slug>-image-prompts.md`。需要公共记忆主题实例时，读 [hindsight 配图 Prompt](../../design/hindsight-shared-memory-image-prompts.md)。技能中不固化某篇文章的张数或节点数量。

## 最短工作流

1. 从成稿选择一个需要视觉解释的判断，确定封面或正文用途。已有图表足够时不重复配图，不按篇幅凑张数。
2. 先写图中要让读者看懂的一句话，再将抽象关系转为具体动作：谁遇到什么 → 操作什么 → 看见什么反馈 → 如何调整。为隐喻标出成立前提与失效边界，不用好看的比喻改变机制。按下方封面/正文逻辑构图，角色按需出场。
3. 先留档公共风格块、角色外形、逐图构图和全部图内文字。每张实际请求的完整 Prompt = 公共风格块 + 对应角色与构图块；关闭额外 Prompt 自动增补，或把实际增补内容一并保存。改角色图优先以已确认图为编辑参考，不仅凭文字重新生成。
4. 优先使用环境提供的 `imagegen` 能力和 `gpt-image-2`。内置入口不可用时说明缺口；经明确指定的网关可用 API 路径。已有授权覆盖本次任务的生成与必要重试，不重复索取同一确认。端点与凭据由运行环境提供，不存入本仓；缺少信息只询问端点及凭据存储标识，不要求发送明文 key。不自行切换模型或用 SVG 冒充生图。错误先区分参数、路由和服务：单路由 503 不代表所有线路不可用；仅在已授权网关内核实同模型的可用路由。上游不支持 WebP 时可先生成 PNG 再本地转 WebP。不盲目重复同一失败请求；同路由同参数重试一次仍失败，先诊断，无法解决则报告具体阻塞。
5. 原图先核对角色、对话、机制、文字与裁切。同一图连续两次不合格，先减少节点或缩短标签，再决定是否继续调用；保留已确认版本。按 AGENTS.md 导出最终 WebP，逐张打开，检查 360px 与桌面效果。发布到文章时另验 Light/Dark、放大入口并运行现有图片门禁与 `git diff --check`；试图不声称已完成文章验收。

## 两套构图逻辑

| | 封面 | 正文 |
| --- | --- | --- |
| 任务 | 让人感知主题与核心矛盾，愿意进入文章 | 让人理解一个判断、关系或机制 |
| 组织 | 一个视觉焦点、一个冲突或悬念；对话可省略或仅留一句 | 一个动作及反馈，或必要的短对话/分镜；不强制三幕 |
| 角色 | 有助于表达主题时出场；无需每次三人齐全 | 按认知任务选角色，动作和交流必须推进理解 |
| 验收 | 缩略图能否辨认主题和主要互动，而非读完整流程？ | 读者能否复述发生什么、为什么变化，以及下一步依据？ |

封面与正文共享形象，不复用同一构图造成开篇重复。插图可以是静态角色互动；需要点击、拖动、实时状态变化时，转交仓库现有交互图能力，不把静态图称作可操作的交互程序。精确关系不能靠角色比喻保真时，保留图表，不强行拟人化。

## 角色图验收

设计提问、探讨、解析、反驳、发现错误、验证正确等交流场景时，读取 [教学节点参考](references/teaching-nodes.md)，实际打开对应图片。复用动作、神态和短话术的组织方式，不照搬例图的技术结论。

- 对照当前参考检查体型、配饰、神态和学长/学员关系；水豚略大且温和引导，不回退到中年导师体态，也不把三人机械画成等高。
- 每句对话有明确说话者，气泡尾部准确；每轮交流推进一个理解动作，不把正文切成三个人轮流朗读。
- 分歧有依据、前提和可验证区别，水豚学长解释结论为何成立；不能只宣布谁对，也不能把事实错误调和成各有道理。
- 学生能用新例子或操作说明理解；生活类比有关键边界。水獭不是永远正确，白猫不是固定犯错者。
- 图中用到的工具能解释操作；配饰可以只负责辨识。不为让小包“有用”硬塞放大镜等无关道具。角色多导致文字变小时，减台词、拆图或减少出场人数。

## 公开留档

正文、Prompt、技能、文件名、图片文字及附带元数据都按公开仓库标准检查：不含内部仓名、公司标识、私人机器名、内网地址、私有链接、个人绝对路径、凭据或真实 Keychain 条目名。公开产品名、公开一手来源和仓库相对资源路径可以保留。不要把交接包、原始对话或网关响应原样复制进仓库。

每张图记录：实际模型、最终完整 Prompt、请求尺寸、生成次数、最终路径、尺寸、字节数和验收状态。未调用就写“未生成 / 0 次”，参数未被服务验证就写“计划参数”；不能把现有图片或失败后残留文件算成本次结果。只记录安全的错误摘要，不保留可能含凭据的请求头或完整响应。

导出过程中的 PNG、临时批处理输入和缓存不提交。确定性 SVG 只用于 AGENTS.md 允许的精确文字或几何场景，且须事先明确说明；若本次明确要求全部模型生图，则不走该替代路径。

## 边界示例

- “给这篇博客配封面并保留 Prompt”：使用本技能。
- “修改文章页布局”：走仓库 CSS 约定，不使用本技能。
- ◐ “图中必须严格按坐标表达比例”：先按仓库规则判断确定性绘图是否更合适，不因本技能偏好而强行生图；本技能只负责适用的配图决策，不替代精确绘制。
